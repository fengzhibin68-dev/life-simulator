# 测试记录 —— MVP 平衡数据

> 数据来自 `node tools/simulate.js 500`（2026-11-02）。
> 三种策略各跑 500 局：随机选 / 总选第一个 / 总选最后一个。

## 一、数据校验

```
通过：25 个事件，5 个结局
```

校验项：id 唯一、必填字段齐全、stage 合法、年龄区间合法、每个事件至少 2 个选项、
`effects` 只含 6 属性 + 4 资源、判定用到的属性合法、5 个结局文案齐全。

## 四、调优过程（问题 → 处理）

| # | 现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | 平均 48 岁死亡，273/300 局早逝 | 压力只涨不降，40 岁后常年 100，每年白扣 3 健康 | 每年压力自然缓解 `-3`（`STRESS_RECOVERY`） |
| 2 | 同上 | 事件健康惩罚过重，叠加自然衰减撑不到 60 | 健康惩罚整体下调约一半 |
| 3 | 「一场病」单个事件能刷 16 次 | 60 岁后复用池的冷却只有 3~5 年 | 60 岁后复用冷却下限提到 8 年；事件重复出现权重递减 |
| 4 | 「事业有成」占 1/3 | 晋升事件可重复，`事业成功` 标签几乎必得 | 晋升改为一次性，难度 55 → 62 |
| 5 | 家庭美满只有 4% | 事业线优先级更高 | **未改**，属于需求 Q2，待产品确认 |

## 五、已知问题

1. **`早逝` 的语义**：当前实现严格按需求 —— 「健康 ≤0 死亡」也算早逝，
   所以 75 岁病故也会显示「早逝」。见 `docs/需求.md` 待确认 Q4。
2. **`end_lonely` 极少**：需要「幸福 <40 且无家庭标签」，而多数角色会结婚，
   随机策略下 500 局只出现 1 次。覆盖率达标，但稀有度偏高。
3. **单局能遇到 24.8/25 个事件**：25 个事件撑一局 80 年，重复不可避免；
   靠冷却 + 权重递减压到「单个事件最多重复 9~12 次」。
4. 移动端已在 400px 宽度下人工核验（属性栏、事件卡、日志三块正常堆叠）。

## 六、怎么复现

```bash
node tools/simulate.js 500
```

数据校验失败时退出码为 1，可用于 CI。
